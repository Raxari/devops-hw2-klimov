# DevOps — домашнее задание 2

Климов И. А., БИСТ-23-ПО-2, вариант 01.

Приложение хранит заметки в PostgreSQL. Dockerfile собирает зависимости
в виртуальном окружении на этапе build и переносит их в чистый образ
python:3.12-alpine. В итоговом образе остаются библиотеки libpq и
mariadb-connector-c; компилятор и заголовки не переносятся.

## Запуск

Нужны Linux (в работе — Ubuntu 24.04 в WSL2), работающий Docker Engine
с поддержкой Swarm, Bash и curl. Команды выполняются из каталога проекта
пользователем с доступом к Docker:

```bash
bash deploy.sh 5.0
```

Скрипт при необходимости включает Swarm и создаёт локальный реестр,
собирает и отправляет образ в реестр, развёртывает стек и выводит /notes.

Параметры варианта: стек klimov-01, две реплики web, порт 8003 → 5001,
PostgreSQL 16 Alpine, подсеть 10.21.0.0/24, реестр localhost:6001,
маркер sitelab. Порт базы на хосте не опубликован. Данные базы хранятся
в именованном томе klimov-01_data, реестра — в klimov-01-registry.
Учебный пароль базы — lab.

## Проверка и обновление

```bash
curl -sS http://127.0.0.1:8003/me; echo
curl -sS -X POST http://127.0.0.1:8003/notes -d 'text=klimov-01-sitelab'; echo
bash deploy.sh 5.1
curl -sS -X POST http://127.0.0.1:8003/notes -d 'text=klimov-01-sitelab-2'; echo
curl -sS http://127.0.0.1:8003/notes; echo
```

Для наблюдения обновления во втором терминале:

```bash
for i in $(seq 60); do
  v=$(curl -s -m 1 http://127.0.0.1:8003/me | grep -o '"version":"[^"]*"' | cut -d'"' -f4)
  echo -n "${v:-ERR} "
  sleep 0.5
done; echo
```

Обновление идёт по одной реплике с порядком start-first. Проверка /notes
контролирует связь приложения с базой; при неудачном обновлении настроен откат.
Повторный запуск той же версии сохраняет заметки в томе базы.

Реестр localhost:6001 рассчитан на одновузловой стенд задания.
